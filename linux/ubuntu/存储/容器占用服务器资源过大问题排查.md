# Docker `/var/lib/docker` 占用过大排查与清理流程

## 1. 问题背景

服务器磁盘空间异常占用，发现 `/var/lib/docker` 目录超过 100G，例如：

```bash
sudo du -sh /var/lib/docker
```

示例结果：

```text
149G    /var/lib/docker
```

但是 Docker 自身统计显示镜像、容器、Volume、Build Cache 占用并不完全匹配：

```bash
docker system df
```

示例结果：

```text
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          27        27        35.75GB   35.75GB (100%)
Containers      30        30        45.88MB   0B (0%)
Local Volumes   51        8         750MB     173MB (23%)
Build Cache     0         0         0B        0B
```

这种情况下，不能直接删除 `/var/lib/docker` 或 `overlay2`，需要先定位具体是哪类目录占用。

---

## 2. 第一阶段：查看 Docker 整体占用

### 2.1 查看 Docker 统计

```bash
docker system df
docker system df -v
```

重点关注：

```text
Images
Containers
Local Volumes
Build Cache
```

含义说明：

| 类型 | 说明 | 常见清理方式 |
|---|---|---|
| Images | Docker 镜像 | `docker image prune -a` |
| Containers | 容器元数据和可写层统计 | `docker container prune` |
| Local Volumes | 本地数据卷 | `docker volume prune`，谨慎使用 |
| Build Cache | 构建缓存 | `docker builder prune -a` |

---

## 3. 第二阶段：定位 `/var/lib/docker` 下具体大目录

执行：

```bash
sudo du -h --max-depth=1 /var/lib/docker | sort -hr
```

或在 `/var/lib/docker` 下执行：

```bash
du -sh ./*
```

本次示例结果：

```text
116K    ./buildkit
74G     ./containers
4.0K    ./engine-id
96M     ./image
304K    ./network
75G     ./overlay2
16K     ./plugins
4.0K    ./runtimes
4.0K    ./swarm
8.0K    ./tmp
737M    ./volumes
```

结论：

```text
/var/lib/docker/containers  74G
/var/lib/docker/overlay2    75G
```

其中 `/var/lib/docker/containers` 占用异常大，优先怀疑是 Docker JSON 日志文件膨胀。

---

## 4. 第三阶段：定位容器日志占用

Docker 默认使用 `json-file` 日志驱动时，容器标准输出会写入：

```text
/var/lib/docker/containers/<container-id>/<container-id>-json.log
```

如果未配置日志轮转，日志可能一直增长到几十 GB。

### 4.1 查询大日志文件

```bash
sudo find /var/lib/docker/containers -name "*-json.log" -type f -exec du -h {} + | sort -hr | head -30
```

本次示例结果：


## 5. 第四阶段：确认大日志对应的容器

可以通过容器 ID 查询对应容器名称、镜像和日志路径。

### 5.1 使用 `docker ps` 查询

```bash
docker ps -a --no-trunc | grep 784c7e88ce88
docker ps -a --no-trunc | grep 1b63e9f854f1
docker ps -a --no-trunc | grep 56182d5627fd
```

### 5.2 使用 `docker inspect` 查询

```bash
docker inspect --format '{{.Name}} {{.Config.Image}} {{.LogPath}}' 784c7e88ce88
docker inspect --format '{{.Name}} {{.Config.Image}} {{.LogPath}}' 1b63e9f854f1
docker inspect --format '{{.Name}} {{.Config.Image}} {{.LogPath}}' 56182d5627fd
```

输出示例：

```text
/container-name image-name /var/lib/docker/containers/xxx/xxx-json.log
```

## 6. 第五阶段：安全清理容器日志

### 6.1 推荐方式：清空日志文件

清空所有容器 JSON 日志：

```bash
sudo find /var/lib/docker/containers -name "*-json.log" -type f -exec truncate -s 0 {} \;
```

这个命令的特点：

- 不删除容器
- 不删除镜像
- 不删除 volume
- 不影响容器文件系统
- 只是把 Docker JSON 日志文件截断为 0 字节

### 6.2 清理后验证

```bash
sudo du -sh /var/lib/docker/containers
sudo du -sh /var/lib/docker
df -h
```

如果本次日志占用约 74G，执行后通常可以立即释放 70G 以上空间。

## 7. 第六阶段：配置 Docker 日志轮转，防止再次爆满

Docker 默认 `json-file` 日志驱动没有大小限制，如果容器持续向 stdout/stderr 输出日志，日志会不断增长。

### 7.1 查看当前 Docker daemon 配置

```bash
cat /etc/docker/daemon.json
```

如果文件不存在，可以新建。

### 7.2 写入日志轮转配置

```bash
sudo mkdir -p /etc/docker

sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  }
}
EOF
```

含义：

```text
max-size: 单个日志文件最大 100MB
max-file: 最多保留 3 个日志文件
```

单个容器最多保留约：

```text
100MB × 3 = 300MB
```

### 7.3 如果已有 `daemon.json`，需要合并配置

例如原配置中已有镜像加速器：

```json
{
  "registry-mirrors": ["https://xxx"]
}
```

应该合并为：

```json
{
  "registry-mirrors": ["https://xxx"],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  }
}
```

不要直接覆盖原有配置，避免影响镜像源、Docker runtime、insecure registries 等配置。

### 7.4 检查 JSON 格式

```bash
cat /etc/docker/daemon.json | python3 -m json.tool
```

如果 JSON 格式正确，会正常格式化输出；如果有错误，会提示具体位置。

### 7.5 重启 Docker

```bash
sudo systemctl restart docker
```

注意：

- 重启 Docker 可能影响正在运行的容器。
- 生产环境建议选择业务低峰期操作。

## 8. docker-compose 中单独限制服务日志

如果不想全局限制，也可以在 `docker-compose.yml` 中对单个服务配置日志轮转。

示例：

```yaml
services:
  app:
    image: your-image
    logging:
      driver: json-file
      options:
        max-size: "100m"
        max-file: "3"
```

然后重启服务：

```bash
docker compose up -d
```

或者旧版本：

```bash
docker-compose up -d
```

## 9. overlay2 占用大的处理原则

本次 `/var/lib/docker/overlay2` 也有约 75G：

```text
75G ./overlay2
```

`overlay2` 是 Docker 镜像层和容器可写层的底层存储目录，不能手动删除。

### 9.1 禁止直接删除

不要执行：

```bash
sudo rm -rf /var/lib/docker/overlay2
sudo rm -rf /var/lib/docker
```

风险：

- Docker 元数据损坏
- 容器无法启动
- 镜像层丢失
- volume 或运行环境异常
- 严重时 Docker daemon 起不来

### 9.2 正确清理方式

清理停止容器：

```bash
docker container prune
```

清理未被容器使用的镜像：

```bash
docker image prune -a
```

清理构建缓存：

```bash
docker builder prune -a
```

组合执行：

```bash
docker container prune
docker image prune -a
docker builder prune -a
```

### 9.3 查看容器写入层大小

如果 `overlay2` 仍然很大，可以查看运行中容器的可写层：

```bash
docker ps -as
```

重点关注 `SIZE` 列。

如果某个容器 `SIZE` 很大，说明它把大量数据写进了容器内部文件系统，而不是写到 volume 或宿主机挂载目录。

常见爆炸目录：

```text
/tmp
/app/logs
/var/log
/root/.cache
/home/*/.cache
```

进入容器检查：

```bash
docker exec -it <container_name_or_id> bash
du -h --max-depth=1 / | sort -hr
```

如果容器没有 bash，可以尝试：

```bash
docker exec -it <container_name_or_id> sh
```

## 11. 一键处理脚本：仅清理 Docker JSON 日志

适合确认问题就是日志膨胀后执行。

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "Before cleanup:"
sudo du -sh /var/lib/docker/containers || true
sudo du -sh /var/lib/docker || true
df -h

echo
echo "Top docker json logs:"
sudo find /var/lib/docker/containers -name "*-json.log" -type f -exec du -h {} + | sort -hr | head -30 || true

echo
echo "Truncating docker json logs..."
sudo find /var/lib/docker/containers -name "*-json.log" -type f -exec truncate -s 0 {} \;

echo
echo "After cleanup:"
sudo du -sh /var/lib/docker/containers || true
sudo du -sh /var/lib/docker || true
df -h

echo
echo "Done."
```

保存为：

```bash
vim clean-docker-json-logs.sh
```

执行：

```bash
chmod +x clean-docker-json-logs.sh
./clean-docker-json-logs.sh
```

## 12. 最终结论

本次 `/var/lib/docker` 占用 149G 的主要原因是：

```text
/var/lib/docker/containers 下的 Docker JSON 日志文件过大
```

其中几个日志文件分别达到：

```text
58G
12G
3.9G
985M
64M
```

解决方式：

1. 使用 `find + du` 定位大日志文件。
2. 使用 `truncate -s 0` 清空日志文件。
3. 配置 `/etc/docker/daemon.json`，启用日志轮转。
4. 重启 Docker，使日志轮转配置生效。
5. 对于 `overlay2`，只能通过 Docker 命令清理，不能手动删除目录。

核心命令：

```bash
sudo find /var/lib/docker/containers -name "*-json.log" -type f -exec truncate -s 0 {} \;
```

核心防复发配置：

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  }
}
```
